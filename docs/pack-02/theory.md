# Теория: что ты будешь знать к 31 августа

30 понятий и терминов, которые закрывает Пак 02. Ты должен уверенно объяснять их смысл на технических собеседованиях.

---

## Блок 1 · Docker и Контейнеризация
1. **Multi-stage build:** метод оптимизации Dockerfile с разделением фаз сборки и runtime для минимизации размера и закрытия уязвимостей.
2. **`COPY --from=<stage>`:** директива переноса артефактов из одного сборочного стейджа в другой.
3. **Non-root user (USER):** запуск процесса внутри контейнера от непривилегированного пользователя для защиты от container escape.
4. **HEALTHCHECK:** инструкция Dockerfile для периодической проверки жизнеспособности процесса внутри контейнера.
5. **PID 1 и обработка сигналов:** процесс с идентификатором 1 в пространстве процессов контейнера, обязанный корректно перехватывать сигналы `SIGTERM` и `SIGKILL`.
6. **Graceful Shutdown:** процесс штатного завершения работы сервиса с закрытием открытых сетевых сокетов и сохранением состояния.
7. **Docker Layer Caching:** механизм кэширования слоев при сборке образов на основе хэшей инструкций и файлов.
8. **`.dockerignore`:** файл исключения временных данных, `.git`, виртуальных окружений из сборочного контекста.

---

## Блок 2 · CI/CD и Доставка
9. **CI/CD Pipeline (Пайплайн):** автоматизированная цепочка последовательных стадий (build, test, deploy) для непрерывной интеграции и доставки.
10. **GitLab Runner (dind):** агент исполнения задач с поддержкой запуска Docker внутри Docker (Docker-in-Docker).
11. **Commit SHA Tagging:** однозначное именование Docker-образов по хэшу коммита (`$CI_COMMIT_SHORT_SHA`) вместо плавающего `:latest`.
12. **Immutable Artifacts (Иммутабельные артефакты):** принцип неизменяемости собранного бинарного образа после прохождения тестов.
13. **SSH-Agent:** утилита для безопасного хранения и использования приватных SSH-ключей в оперативной памяти процесса без записи на диск.
14. **`known_hosts` и `ssh-keyscan`:** проверка подлинности публичного ключа сервера для защиты от атак Man-in-the-Middle (MitM).
15. **CI/CD Variables (Секреты):** механизм безопасной передачи паролей и токенов с флагами Protected и Masked.
16. **DORA Metrics:** четыре ключевые метрики эффективности DevOps-процессов (Deployment Frequency, Lead Time, Change Failure Rate, MTTR).

## Блок 3 · Надежность, Откат и Сети
17. **Rollback (Откат):** детерминированная процедура возврата инфраструктуры к предыдущему заведомо работоспособному состоянию.
18. **Rollback Runbook:** пошаговый регламент действий дежурного инженера при экстренном откате релиза.
19. **Mean Time to Recovery (MTTR):** среднее время восстановления работоспособности сервиса после инцидента.
20. **PR Conventions (Правило №2):** регламент описания Merge Request с обязательными блоками: суть изменений, радиус поражения (blast radius) и план отката.
21. **Blast Radius (Радиус поражения):** масштаб потенциального ущерба в инфраструктуре в случае ошибки в конфигурации или коде.
22. **Reverse Proxy:** сервер-посредник (Nginx), принимающий клиентские запросы и перенаправляющий их на внутренние сервисы.
23. **Заголовок `Host`:** HTTP-заголовок, указывающий доменное имя, запрошенное клиентом.
24. **Заголовок `X-Real-IP`:** заголовок, содержащий прямой IP-адрес входящего соединения.
25. **Заголовок `X-Forwarded-For`:** заголовок со списком IP-адресов всех промежуточных прокси-серверов.
26. **Заголовок `X-Forwarded-Proto`:** протокол (http или https), использованный клиентом при обращении.
27. **Трёхстороннее рукопожатие (TCP Handshake: SYN -> SYN-ACK -> ACK):** трехэтапное установление надежного TCP-соединения между клиентом и сервером.
28. **Флаг `RST` (Reset):** пакет аварийного сброса TCP-соединения при попытке обращения к закрытому порту.
29. **Диагностика `ss -tulpn`:** утилита Socket Statistics для моментального анализа слушающих сокетов ядра через Netlink.
30. **No manual mutation (Правило №1):** запрет на внесение ручных изменений на сервере в обход версионированных скриптов и манифестов.
