## Задача 2.1: Multi-stage Dockerfile
- **Вопрос:** Зачем мы разделяем сборку на stage `builder` и stage `runtime`?
  - 🟢 *Зеленый флаг:* «Чтобы в итоговый образ не попали компиляторы gcc, исходные тексты и кэш пакетов. Это уменьшает размер образа в разы и снижает поверхность атаки».
  - 🔴 *Красный флаг:* «Так просто принято в Docker».
- **Вопрос:** Почему нельзя запускать контейнеры от пользователя `root`?
  - 🟢 *Зеленый флаг:* «Ядро Linux общее для хоста и контейнера. При уязвимости в приложении злоумышленник с root-правами может совершить container escape и захватить хостовую систему».
  - 🔴 *Красный флаг:* «Root в контейнере занимает больше памяти».

## Задача 2.2: CD Пайплайн и SSH Deploy
- **Вопрос:** Почему в GitLab CI деплоить с тегом `:latest` — это плохая практика?
  - 🟢 *Зеленый флаг:* «Теряется связь с кодом в Git, невозможно детерминированно откатиться на прошлую версию, а docker compose pull может не обновить слои из-за локального кэша».
  - 🔴 *Красный флаг:* «Потому что latest работает медленнее».
- **Вопрос:** Как безопасно передать SSH-ключ для деплоя на целевую виртуальную машину?
  - 🟢 *Зеленый флаг:* «Сохранить приватный ключ в GitLab CI/CD Variables как защищенную и замаскированную переменную, а в пайплайне загрузить в `ssh-agent` через `ssh-add`».
  - 🔴 *Красный флаг:* «Закоммитить id_rsa в репозиторий».

## Задача 2.3: Быстрый откат (Rollback)
- **Вопрос:** Что делать, если после релиза сервис начал отвечать 500-ми ошибками?
  - 🟢 *Зеленый флаг:* «Немедленно открыть runbook-rollback.md, взять предыдущий стабильный commit SHA и перезапустить контейнер командой `IMAGE_TAG=<STABLE_SHA> docker compose up -d`, уложившись в MTTR <1 мин».
  - 🔴 *Красный флаг:* «Начать срочно кодить хотфикс в main».
