# Пак 03: Prometheus с нуля, Мониторинг 3 VM и Архитектура Наблюдаемости

!!! info "Статус: Запланирован на сентябрь (1–14 сентября 2026)"
    Сентябрьский спринт. Фокус на построении полноценного мониторинга инфраструктуры и сервисов с нуля, понимании time-series баз данных, сборе системных метрик и написании PromQL запросов.

---

## 🎯 Ключевые цели спринта

1. **Развёртывание Prometheus с нуля на 3 виртуальных машинах**
    * Stand 1: Сервер Prometheus и хранилище TSDB.
    * Stand 2: GitLab Runner VM.
    * Stand 3: Production / Staging Application Server.
    * Ручная конфигурация `prometheus.yml` (scrape targets, scrape interval, evaluation interval).

2. **Пошаговая архитектурная схема в Excalidraw**
    * 10 уровней топологии: ВМ, сети (Host-Only, Internal, NAT), сервисы, экспортеры (`node_exporter`, `cAdvisor`, `Promtail`).
    * Потоки данных: Prometheus Scrape Loop (Pull-модель), Alertmanager $\to$ Telegram (Alerting), Loki $\to$ Promtail (Push логов) и Grafana.
    * Ключевой визуальный артефакт в инженерном портфолио для защиты архитектуры на собеседованиях.

3. **Сбор метрик ОС и контейнеров (`node_exporter` & `cAdvisor`)**
    * Установка и запуск `node_exporter` через `systemd` как системной службы.
    * Запуск `cAdvisor` для профилирования и мониторинга Docker-контейнеров.
    * Контроль использования ресурсов ядра: CPU iowait, saturation, memory cgroup limits.

4. **Практика PromQL и анализ производительности**
    * Векторные операции, мгновенные и интервальные векторы (`instant` vs `range vectors`).
    * Вычисление реальной утилизации CPU с фильтрацией `mode="idle"`.
    * Мониторинг насыщения файловых дескрипторов и дискового пространства.

5. **Правила алертинга и подготовка к оповещениям**
    * Синтаксис Alerting Rules в Prometheus.
    * Условия `for: 5m` для предотвращения ложных срабатываний (flapping).
