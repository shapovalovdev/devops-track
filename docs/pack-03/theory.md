## Блок 1 · Сети и сокеты в Linux
1. **Network Socket (Сетевой сокет):** программная конечная точка сетевого соединения, представленная в Linux как файловый дескриптор.
2. **Флаги `ss -tulpn`:** TCP, UDP, Listening, Process name/PID, Numeric format.
3. **`lsof` (List Open Files):** утилита для поиска открытых файлов, сокетов и сетевых портов процесса.
4. **`0.0.0.0` (INADDR_ANY) vs `127.0.0.1` (loopback):** привязка ко всем интерфейсам против привязки только к локальному стеку хоста.
5. **Listening vs Established:** состояние сокета, ожидающего подключение, против активного установленного соединения.
6. **Kernel Routing Table:** таблица правил ядра Linux (`ip route`), определяющая маршрут отправки пакетов.
7. **Default Gateway (Шлюз по умолчанию):** IP-адрес маршрутизатора, на который отправляется трафик, не попадающий в локальные подсети.
8. **Routing Metric (Метрика маршрута):** числовой приоритет маршрута при наличии нескольких шлюзов.
9. **`ip route get <IP>`:** команда ядра для симуляции и проверки выбора маршрута до конкретного адреса.
10. **Трёхстороннее рукопожатие (TCP Handshake: SYN -> SYN-ACK -> ACK):** трехэтапное установление надежного TCP-соединения, согласование sequence numbers и параметров сессии.
11. **Internal Network vs Host-Only vs NAT:** типы виртуальных адаптеров VirtualBox и их назначение.

## Блок 2 · Архитектура Prometheus и Телеметрия
12: **Pull-модель:** архитектурный паттерн сбора метрик, при котором сервер мониторинга сам опрашивает конечные точки по расписанию.
13. **Scrape Interval & Evaluation Interval:** интервал опроса таргетов и интервал вычисления правил алертинга.
14. **Scrape Target:** эндпоинт (IP:Port/metrics), опрашиваемый Prometheus.
15. **Target Status (`UP` == 1 / `DOWN` == 0):** внутренняя синтетическая метрика `up`, фиксирующая доступность эндпоинта.
16. **`node_exporter`:** агент для сбора системных метрик Linux (CPU, память, диск, сеть, load average).
17. **`cAdvisor`:** агент Google для мониторинга ресурсов контейнеров Docker через cgroups.
18. **Time Series (Временной ряд):** последовательность пар (timestamp, float value), идентифицируемая именем метрики и набором лейблов (`key=value`).
19. **Metric Types (Типы метрик):**
    - **Counter:** монотонно растущий счетчик (например, общее число HTTP-запросов).
    - **Gauge:** числовое значение, которое может произвольно расти и падать (температура, объем свободной памяти).
    - **Histogram:** распределение значений по корзинам (buckets) для расчета перцентилей (p95, p99 latency).
20. **PromQL:** функциональный язык запросов к временным рядам Prometheus.
21. **Instant Vector vs Range Vector:** срез значений на текущий момент времени против набора значений за интервал времени (`[5m]`).
22. **Функция `rate()`:** расчет среднего темпа прироста счетчика в секунду с коррекцией на сбросы при перезапусках.
23. **Функция `increase()`:** абсолютный прирост счетчика за указанный временной диапазон.
24. **High Cardinality:** антипаттерн вставки уникальных данных (user_id, IP клиентов) в лейблы метрик, приводящий к взрыву объема памяти базы временных рядов (TSDB).

## Блок 3 · CI/CD и Эксплуатация
25. **Immutable Artifacts (Иммутабельные артефакты):** принцип неизменяемости собранного Docker-образа после прохождения пайплайна.
26. **Commit SHA Tagging:** именование образов хэшем коммита `$CI_COMMIT_SHORT_SHA` вместо `:latest`.
27. **Rollback Determinism:** способность гарантированно вернуть работоспособную версию деплоем конкретного тега коммита.
28. **Excalidraw Architecture Schema:** наглядное графическое представление сервисов, подсетей и портов.
29. **Constitution Rule 1 (No manual mutation):** запрет на внесение изменений на продакшн-стенде в обход системы контроля версий.
30. **Constitution Rule 2 (PR & Blast Radius):** фиксация рисков и плана отката в описании каждого изменения.
31. **Time to Recovery (TTR):** ключевая метрика надежности — время от детекции инцидента до восстановления работоспособности.
32. **Hand-Earned Skill:** навык, добытый самостоятельным набором конфигураций и команд без слепого копирования ИИ.
