## Задача 1.1: Сетевая диагностика
- **Вопрос:** Что делает команда `sudo ss -tulpn` и почему ядро скрывает PID процесса, если выполнить её без `sudo`?
  - 🟢 *Зеленый флаг:* Четко расшифровываешь каждый флаг: TCP, UDP, Listening, Processes, Numeric. Объясняешь, что сокет чужого процесса в ядре защищен правами доступа.
  - 🔴 *Красный флаг:* Путаешься во флагах или говоришь «это просто показывает порты».
- **Вопрос:** Если сервис слушает `127.0.0.1:5000`, сможет ли до него достучаться другая ВМ в локальной сети?
  - 🟢 *Зеленый флаг:* «Нет, loopback слушает только локальный стек ОС. Чтобы отвечать наружу, нужно слушать 0.0.0.0 или IP локального интерфейса».
  - 🔴 *Красный флаг:* «Да, если прописать IP хоста».

## Задача 1.2: Архитектурная схема мониторинга в Excalidraw
- **Вопрос:** Объясни по своей схеме, как пакет из браузера на хост-ноутбуке попадает в контейнер приложения на `vm1-simpleapp`?
  - 🟢 *Зеленый флаг:* Показываешь цепочку: Браузер $\to$ Host-Only IP `vm1` $\to$ порт 80 (Nginx) $\to$ Docker bridge сеть $\to$ порт 5000 контейнера simpleapp.
  - 🔴 *Красный флаг:* Путаешься в IP-адресах или не можешь объяснить роль Nginx reverse proxy.
- **Вопрос:** В какую сторону направлены стрелки сбора метрик между Prometheus и экспортерами и почему?
  - 🟢 *Зеленый флаг:* «Стрелка строго от Prometheus к node_exporter / cAdvisor, потому что Prometheus сам инициирует HTTP GET запрос на эндпоинт `/metrics` по расписанию (Pull-модель)».
  - 🔴 *Красный флаг:* «Стрелка от нод к Прометею, потому что ноды отправляют метрики».
- **Вопрос:** Как по схеме проходит алерт от момента падения сервиса до уведомления в Telegram?
  - 🟢 *Зеленый флаг:* Сбой на ноде $\to$ Prometheus фиксирует `up == 0` в цикле Scrape Loop $\to$ через `evaluation_interval` срабатывает Alerting Rule $\to$ Prometheus отправляет POST в `Alertmanager :9093` $\to$ Alertmanager дедуплицирует и отправляет Webhook в Telegram Bot API.
  - 🔴 *Красный флаг:* «Prometheus сам шлет сообщение в Telegram напрямую».

## Задача 2.1: Prometheus + node_exporter
- **Вопрос:** Как Prometheus узнает, что виртуальная машина `vm3-runner` упала?
  - 🟢 *Зеленый флаг:* «Prometheus регулярно делает HTTP GET на `http://192.168.56.30:9100/metrics`. Если запрос завершился таймаутом или ошибкой, метрика `up{instance="192.168.56.30:9100"}` становится равной 0».
  - 🔴 *Красный флаг:* «ВМ присылает алерт в Прометей».

## Задача 2.2: cAdvisor
- **Вопрос:** Зачем нужен cAdvisor, если уже стоит `node_exporter`?
  - 🟢 *Зеленый флаг:* «node_exporter собирает метрики всей операционной системы, а cAdvisor считывает cgroups конкретных контейнеров Docker и показывает потребление каждого контейнера отдельно».
  - 🔴 *Красный флаг:* «cAdvisor — это то же самое, просто от Google».

## Задача 2.3: CI/CD Tagging
- **Вопрос:** Почему в GitLab CI деплоить с тегом `:latest` — это плохая практика?
  - 🟢 *Зеленый флаг:* «Теряется связь с кодом в Git, невозможно надежно откатиться на старую версию, а docker pull может не обновить слои из-за кэша».
