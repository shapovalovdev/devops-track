## Трек 1 — Фундамент

### ☐ 1.1 Схема стенда · A · ~1.5 ч
- Нарисовать: контейнеры, docker-сети, опубликованные порты, внутренние порты, кто с кем и по какому адресу.
- Охватить: Nginx, Grafana, Loki, БД, GitLab, runner.
- Инструмент любой (Excalidraw, draw.io, бумага + фото).
- **Готово:** схема в репозитории.

### ☐ 1.2 Docker networking · A или D · ~2 ч
- `bridge` по умолчанию vs пользовательская bridge vs `host`.
- Резолв по имени сервиса: где работает, где нет.
- `ports:` vs `expose:` в compose.
- `localhost` внутри контейнера.
- `docker network ls`, `docker network inspect`, `docker inspect`.
- Всё проверить на своём стенде: `docker exec -it <c> sh`, пинг соседей по имени и по IP.
- **Готово:** на схеме из 1.1 можешь показать, почему контейнер X видит или не видит контейнер Y.

### ☐ 1.3 TCP и диагностика · A · ~2 ч
Проследить один реальный запрос (браузер → Nginx → Grafana):
- `curl -v` — разобрать вывод построчно.
- `ss -tulpn` — кто слушает, на каком интерфейсе (`0.0.0.0` vs `127.0.0.1`).
- `dig` / `nslookup` — резолв снаружи и внутри docker-сети.
- `tcpdump -i any port 3000 -nn` — увидеть SYN → SYN-ACK → ACK.
- `ip route`, `ip addr`.
- **Готово:** файл `network-cheatsheet.md` — команды, которые запускал сам, с примерами вывода и пометками.

### ☐ [+] 1.3s · Разобрать разницу `127.0.0.1` vs `0.0.0.0` в `ports:` снаружи VM и что это значит для безопасности.

## Трек 2 — Практика

### ☐ 2.1 Диагностика поломки · A · ~2–3 ч · **МИНИМУМ**
- Завести `debug-gitlab-runner.md`, вести по ходу:
  ```
  Гипотеза N: ...
    Как проверил: ...
    Результат:    ...
    Вывод:        подтвердилась / отпала
  ```
- Проверить как минимум: общая ли docker-сеть; по какому URL runner идёт в GitLab и достижим ли он изнутри контейнера runner-а; `docker logs` обоих; `gitlab-runner verify`; виден ли runner в Admin → Runners; `external_url` GitLab-а.
- Отпавшие гипотезы не удалять.
- **Готово:** ≥ 3–4 проверенные гипотезы, включая отпавшие.

### ☐ 2.2 Починить · A · ~1–2 ч · **МИНИМУМ**
- Runner зарегистрирован, виден в GitLab, берёт джобы.
- `.gitlab-ci.yml` с одной джобой `echo "hello"`.
- **Готово:** зелёный pipeline. Скриншот в отчёт.

### ☐ 2.3 Pipeline: сборка образа · A · ~3 ч
- Стадии `build` → `push`.
- Образ одного из своих сервисов уходит в GitLab Container Registry.
- Тег по commit SHA, не `latest`.
- **Готово:** образ появляется в registry после пуша в ветку.

### ☐ [+] 2.3s · Стадия `lint` (hadolint) до сборки.

### ☐ [+] 2.4 Автодеплой · A · ~2–3 ч
- Стадия `deploy`: обновление контейнера на VM свежим образом. SSH допустим.

### ☐ 2.5 README проекта · C · ~1.5 ч
- Что за система, схема из 1.1, состав, как поднять, какие решения и почему, что бы сделал иначе.
